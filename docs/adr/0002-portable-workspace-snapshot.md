# Portable workspace restoration

Cross-provider handoff must preserve dirty files, deletions, unignored untracked files, modes, Git HEAD and staged state. A clone loses that state, provider-native checkpoint IDs cannot cross providers, and embedding an archive in a context request would copy file bytes into consumer journals. Extend `WorkspaceRequest` with a reference-only projection of Runtime's canonical candidate workspace snapshot. Bind both the file manifest and archive references, plus the existing source lease and policy identities, in the accepted request. Runtime owns capture, artifact verification and restoration; adapters own transport and readiness. A snapshot cannot compete with a repository or native checkpoint source, and its working directory is relative to the restored repository.

The receiver authorizes each closed S3, IPFS or private CAS reference for the accepted operation. Hashes prove content identity, not authorization. The source owner holds its private workspace lease throughout capture; a public lease record grants no control. Runtime bounds and verifies artifacts before restore, publishes through fresh owned staging, and refuses an occupied or concurrently populated destination without changing it. Adapters refuse snapshot input before credentials, provisioning or native admission until their deployed receiver passes the restore fixture. A configured boolean, mapper or HTTP method alone does not qualify support.

Before preview, the planner places `agentWorkspaceSnapshotRefDigest(snapshot)` in `destination.workspaceSnapshotDigest`. The existing plan digest then commits the workspace choice, acceptance commits that plan digest, and the transfer schema checks it against the complete snapshot reference. Recomputing the request hash cannot substitute another archive after acceptance. An independent acceptance field was rejected because the accepted plan already owns destination identity.
