# Read-only environment discovery

Runtime must inspect unknown retained custody before it can authorize a reconnect. The existing get may resume a sandbox and install native execution support, so qualified providers opt in through the same get with literal `readOnly: true`, returning a non-executable public custody snapshot. Expired installed leaf and parent receipts are metadata for recovery, never dispatch authority; control-plane reads replace unavailable stopped-guest probes. The canonical `AgentEnvironmentReadOnlyGetOptionsSchema` admits only this flag and cancellation. The existing `AgentEnvironmentGetOptionsSchema` remains strict and excludes the new key: widening it would make old published providers dynamically accept the flag and still execute ordinary reconnect. Unsupported adapters refuse before lookup. Consumers must use a qualified provider cohort and never fall back to ordinary get; package owners supply actual published floors. The maintained control-artifact checker can consume an already installed cohort with `--read-only-consumer`, verifies that an old registry Provider resolves the candidate canonical archive, and proves its refusal before lookup alongside the current snapshot's zero mutation behavior.
